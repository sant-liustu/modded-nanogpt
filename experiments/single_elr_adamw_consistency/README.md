# Single-ELR AdamW consistency experiment

## Question

Does standard AdamW retain its loss trajectory when the 72 Transformer block matrices
use the same externally supplied effective learning rate (ELR), while the tied
embedding/head uses twice that ELR?

The controlled quantity is

```text
ELR_i(t) = learning_rate_i(t) / RMS(W_i(t))
```

and the controller applies

```text
block_learning_rate_i(t) = target_elr(t) * RMS(W_i(t))
embedding_learning_rate(t) = 2 * target_elr(t) * RMS(W_embedding(t)).
```

## Fixed experiment scope

- Source baseline: the B128 RMSNorm-gamma AdamW trainer with weight decay 0.1.
- Controlled parameters: every trainable parameter with `ndim == 2`. The 72 Transformer
  block matrices share `target_elr`; the tied embedding/language-model-head matrix uses
  `2 * target_elr` (73 controlled tensors total).
- Excluded parameters: all one-dimensional RMSNorm gamma parameters. They remain on
  their original AdamW learning-rate schedule and use zero weight decay.
- AdamW weight decay on controlled matrices remains fixed at `0.1`. There is no
  compensation for changes in `learning_rate_i * weight_decay`.
- The ELR trajectory is supplied externally and is not generated by this experiment.

## Reference-file contract

By default the trainer reads:

```text
experiments/single_elr_adamw_consistency/single_elr_reference.jsonl
```

Override the path with the `SINGLE_ELR_REFERENCE_JSON` environment variable.
The file must contain exactly one JSON object for every optimizer update from 1 through
20400:

```json
{"update_step": 1, "target_elr": 1.23e-6}
{"update_step": 2, "target_elr": 2.46e-6}
```

`target_elr` is the equal-tensor arithmetic mean of the 72 non-embedding block-matrix
ELRs in the source AdamW run. It uses the `learning_rate / parameter RMS` convention.
The trainer applies the embedding multiplier internally; the JSONL must not multiply
the target by two. Duplicate, missing, non-finite, zero, or negative targets are
rejected before training starts.

Generate the replay reference from the completed `wd0.1` AdamW telemetry:

```powershell
python experiments/single_elr_adamw_consistency/build_single_elr_reference_from_adamw.py
```

The builder reads the 72 non-embedding matrix RMS histories, linearly interpolates the
four-step telemetry cadence to every pre-update step, applies the baseline block WSD
learning rate, and writes the equal-tensor arithmetic mean ELR for updates 1–20400.

## Implementation plan

1. Keep the model, data, seed, AdamW betas, validation cadence, and training length of
   the standard baseline unchanged.
2. Put each controlled 2-D tensor in its own ordinary `torch.optim.AdamW` parameter
   group so that it can receive its own scalar learning rate without changing AdamW's
   moment equations.
3. Before every optimizer step, calculate all tensor RMS values, set each block group
   from the supplied scalar ELR and the tied embedding group from twice that ELR, then
   perform the ordinary AdamW step.
4. Keep RMSNorm gamma in a separate AdamW optimizer driven by the baseline WSD schedule.
5. Log compact controller summaries every four updates and per-tensor details every
   1000 updates.

## Review focus and risks

- Verify that the controlled set contains exactly the intended 2-D tensors.
- Verify that the controller runs before the optimizer snapshot and optimizer step.
- Verify that the logged actual ELR equals the target ELR within floating-point error.
- One AdamW parameter group per tensor is deliberately simple and auditable, but may be
  slower than the baseline fused two-group optimizer. Runtime overhead must be measured
  before launching the full 20400-step run.
- A supplied trajectory copied from a completed AdamW run is a replay target. This
  experiment tests implementation consistency; it is not by itself a prospective ELR
  prediction result.

## Fast smoke test

From the repository root:

```powershell
python experiments/single_elr_adamw_consistency/smoke_test_optimizer_groups.py
```

This does not launch model training. It checks that the installed PyTorch can execute
73 independent standard-AdamW parameter groups, that gamma remains in its own optimizer,
and that the applied `learning_rate / RMS` agrees with the block target and the tied
embedding target is exactly twice the block target.
